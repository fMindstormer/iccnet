These PNGs hold no picture. Each pixel stores its own coordinates, and the color profile embedded in the file holds a small neural network. A color engine that runs the profile paints a painting; your browser does not run it, and shows the coordinates.

Inside the profile

The D2B1 tag of the selected profile, element by element, read from the PNG above by this page. D2B0 to D2B3 point at the same bytes. Pick an element to see its curves or its matrix.

What fourteen channels can draw

LittleCMS reads matrices with at most 15 inputs and outputs, and the gate takes one, so every hidden layer is 14 wide. A curve, though, can hold thousands of samples: learned curves carry most of the picture.

How it works

  1. ICC v4 profiles can carry D2B tags of type multiProcessElements: a chain of matrices with offsets and sets of per-channel curves, in float, never clipped between elements. A matrix and a set of curves make one neural-network layer.
  2. Activations are segmented curves: ReLU is two formula segments that meet at 0, and a learned activation is one sampled segment of 64 points per neuron. The network ends in a sigmoid, the sRGB curve and the sRGB-to-XYZ matrix, and the engine's conversion to the screen undoes the last two.
  3. The other tags say plain sRGB. Engines that skip D2B tags (ColorSync, Chrome's skcms, Firefox's qcms) use those and show the coordinates. LittleCMS reads D2B first, and so do ImageMagick, sharp, libvips, Pillow, GIMP and Krita, which use it.
  4. One channel is a gate that paints blue = 0 black. Black point compensation makes LittleCMS evaluate the profile at RGB 0, 0, 0, and versions 2.14 to 2.19 disagree about what a color there means.
